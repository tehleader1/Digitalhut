# DigitalHut SEO Framework Capacity Plan

Date: 2026-06-30

Purpose: clarify that the deeper "Pro" reference is about the operator's Codex capacity for building DigitalHut, not a public DigitalHut subscription promise.

## Core Distinction

DigitalHut customer tiers:

- control visitor experience depth
- unlock longer AI descriptions
- retain more history
- connect to node progress
- stage future backend editing
- support downloads, saved notes, and account records

Codex operating capacity:

- supports long-context build work
- holds the full SEO framework in memory during updates
- compares competitor behavior
- maps FireCuda evidence
- updates docs/code/pages
- runs verification
- produces tighter follow-up instructions

These are separate systems.

## Why Higher Operating Capacity Matters

The DigitalHut runner job is not a small chatbot task. It requires several live tracks at the same time:

1. Keyword framework:
   - broad search roots
   - long-tail phrases
   - off-tier market language
   - Google Images-friendly thumbnail names
   - blog clusters

2. Competitor checks:
   - 3D model sites
   - GLB marketplaces
   - image search behavior
   - presentation platforms
   - observatory/science visualization references

3. Product verification:
   - renderer load path
   - thumbnail-to-render path
   - blog route
   - insight map
   - pixel events
   - Supabase-backed activity

4. FireCuda evidence:
   - original captures
   - optimized GLBs
   - thumbnails
   - failed renders
   - winning assets
   - reports
   - backlink notes

5. Deployment control:
   - targeted commits
   - build checks
   - avoid staging huge GLBs accidentally
   - keep Vite/Vercel stable

## Manual Runner Cycle With Capacity

Every serious runner pass should produce:

- one concrete code/doc/content change
- one evidence record
- one verification command or reason it was not run
- one next measurement

Minimum cycle:

1. Inspect current evidence.
2. Pick the highest-value SEO/render gap.
3. Patch the site or docs.
4. Verify the build or route.
5. Record the result.
6. Decide the next keyword/render/backlink test.

## Current Priority

The current priority is the SEO evidence loop:

thumbnail image -> blog/report -> Play Preview or renderer -> pixel event -> insight map -> keyword adjustment -> FireCuda archive.

Until this loop is producing consistent data, do not over-focus on public automation claims. The strongest business signal is whether real people click from a search/blog/thumbnail surface into a working 3D render.

## Public Copy Boundary

Do not say:

- "Codex Pro is required for DigitalHut users."
- "DigitalHut customers buy Codex Pro."
- "The runner is autonomous if the reasoning bridge is not funded and verified."

Say:

- "DigitalHut uses an internal manual runner process for SEO, renderer testing, FireCuda evidence mapping, and product verification."
- "Customer tiers control experience depth inside DigitalHut."
- "Operator capacity controls how deeply the builder can research, update, verify, and preserve the system."
