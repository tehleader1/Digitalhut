# DigitalHut Business Model Experiment Lab

DigitalHut should not bottleneck itself into subscriptions only. The system should monitor multiple models at once and let client behavior decide what surfaces.

Core rule: subscriptions are one monetization route, not the master model. Any legitimate value path can prepare a verified package back to the DigitalHut treasury wallet if it is measurable, safe, and connected to the observatory experience.

## Active Experiment Lanes

- SEO observatory engine
- contract redlining assistance
- subscription access
- treasury support
- commissioned real-world GLB assets
- sponsor lanes
- paid observatory reports
- asset licenses
- backend conversion credits
- database intelligence
- cloud rendering and conversion
- mining/compute research

## Rules

### SEO

Use verified renderable assets, blogs, ratings, reviews, backlinks, and category pages to build search value. This is the safest long-term growth lane.

### Contract Redlining

DigitalHut can assist with comparing contract clauses, creator commission language, sponsorship terms, and asset licenses. It should not present itself as legal counsel. Human/legal review is required before signing.

### Subscription Models

Standard, Premium, and Pro should remain active, but they should not be the only path. Nodes, downloads, backend editing, creator tools, and sponsor lanes can exist beside subscriptions.

Subscription language must not make DigitalHut feel locked behind one model. Guests and wallet-connected users can still experience the public observatory. Paid tiers expand depth, saved history, backend controls, nodes, and research capacity.

### Treasury Support

Treasury support is an open support lane for people who want to fund the build without buying a set tier.

Possible purposes:

- renderer uptime
- SEO tests
- FireCuda archive work
- verified GLB cleanup
- thumbnail generation
- public blog/report testing
- community testing

This lane should still use wallet verification and receipt records. It is not a hidden donation flow.

### Commissioned GLB Assets

Creators and field teams can be paid for real-world GLB assets only after quality is verified:

- render success
- source rights
- usable preview
- category fit
- SEO page fit
- expected revenue or sponsor value

### Paid Observatory Reports

Paid reports can exist when a client wants DigitalHut to turn a real topic into a structured 3D observatory report.

Examples:

- real estate area report
- tourist/travel report
- science/research visualization
- local business presentation
- market/stock visual context
- public situation report

Rule: do not sell a report if the render path, source notes, or thumbnail path cannot be verified.

### Asset Licenses

Verified DigitalHut assets can become licensable only after:

- source rights are clear
- GLB render is verified
- thumbnail is usable
- category and blog page fit
- download/share path is known
- sponsor/backlink terms are understood

Asset licensing should be measured by asset views, download intent, ratings, review text, and backlink value.

### Mining / Cloud Mining

No browser mining. No silent device mining. No visitor CPU/GPU usage without explicit opt-in and legal/security review.

Allowed research:

- opt-in compute credits
- third-party cloud-rendering economics
- render-credit simulations
- sponsor-funded conversion queues
- backend provider pricing comparisons

Mining-adjacent work must never slow down the public renderer.

## Surface Logic

The model that should surface is the model with the best combination of:

- client interest
- trust
- revenue potential
- compliance safety
- renderer fit

## Treasury Route Rule

Every revenue lane should prepare a package before payment:

1. What is the user funding?
2. Which asset/report/category/node/tier/sponsor lane is involved?
3. What does the user receive?
4. What wallet/chain/amount/receiver is expected?
5. What receipt or confirmation proves it?
6. What Supabase/FireCuda record preserves it?

The treasury wallet should appear naturally through verified packages, not as pressure to buy one preset model.
